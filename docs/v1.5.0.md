# SSH Key Manager v1.5.0

Version 1.5 is a security-hardening release focused on SSH transport correctness,
host identity, safe fleet operations, and release provenance.

## Highlights

- remote installs are version-pinned and fail closed when release assets are unavailable;
- downloaded artifacts must match the expected embedded version in addition to SHA-256;
- SKM transport uses `IdentitiesOnly=yes` whenever the managed key exists;
- `skm host fingerprint/trust/verify/untrust` adds explicit SSH host-key pinning;
- `host show/edit/rename/remove --force` makes machine lifecycle policy-aware;
- only one saved alias may represent the local SKM node;
- `skm sync identities MACHINE --dry-run` previews registry changes;
- sync preflight refuses to invalidate the remote node's desired-state policy;
- timestamped metadata backups have bounded retention (five by default);
- audit/policy JSON includes stable structured `findings` while retaining `issues`;
- local managed-key paths/symlinks and generated key comments receive stricter validation;
- `skm doctor` now reports broader trust/filesystem/host-pin health;
- CI includes a real OpenSSH daemon test proving agent keys cannot bypass the managed identity;
- releases include a source-commit manifest and GitHub build-provenance attestation.

## Upgrade notes

No registry or policy migration is required from v1.4. Existing remote hosts remain
unpinned until you explicitly trust them, so upgrading does not replace your
current host-key behavior automatically.

The intentional behavior change is management identity selection: if a host was
reachable only because ssh-agent or a default SSH key happened to authenticate,
`skm host test` may now fail once an SKM managed key exists. That is correct: grant
the SKM managed public key explicitly rather than relying on an unrelated identity.

Recommended post-upgrade checks:

```bash
skm doctor
skm policy check
skm audit
skm sync identities REMOTE --dry-run
```

For important hosts, independently verify the server fingerprint before pinning:

```bash
skm host fingerprint REMOTE
skm host trust REMOTE 'SHA256:...'
skm host verify REMOTE
```
